# V6 判决书（2026-10-17）

> 用一句话说清：**这是一台非常精密的进化引擎，装在一个鞋盒大小的世界里。**
> 它的机制做对了，它的容量被卡死了。修 P0 之前，「自演化」这个主张在历史上
> **从未被兑现过**；修完之后，才能诚实看到 —— 卡住它的不是机器，是任务源。

本文所有结论都带读数出处。口径一句话：**读到什么算什么，读不到就说读不到。**

## 1. 正方：哪些是真的做对了

### 1.1 没有死库存 —— 这是罕见的

AST 扫全部相对导入后统计：**零引用的模块只有 `__main__.py`（27 行）**。
所有 >150 行的模块都至少被 `cli.py` 或某份契约引用到。

对照 V5（252 个死库存技能），这是实质性的进步：**这个仓库维护得动**。

### 1.2 它的判据严厉到能抓出我自己三次错误

这是最硬的证据。近三轮修 bug 时，被系统当场驳回的有：

| 轮次 | 我做的「优化」 | 被谁抓到 |
|---|---|---|
| r44 | 跳过「基线没通过的题」省回归时间 | `contract_nongression` C2 / **G5**（G5 = runner 全崩时闸**放行**，真 fail-open） |
| r45 | 探针里两次 reason 不同却断言该去重 | 探针与被测不同源，19/19 自检暴露 |
| r46 | 契约 B 组替被测代码补写那条事件 | 自查认定为**测试伪造结果**，改回 |

一个你自己能骗过自己的系统没有价值。**这套判据把我三次改建驳回了，说明它有牙。**

### 1.3 它知道自己没事可做就停下

单次 `--rounds 8` 实测：

```
轮1  reward 0.0 → 0.6   commit  add_skill:fix_control_flow
轮2  reward 0.6 → 1.0   commit  add_skill:fix_literals
轮3  no_weakness_evidence（无失败证据 ⇒ 不提议）  idle
轮4  idle_streak=2 ⇒ evolution.stopped「不是失败」
```

`evolution.stopped` 的 payload 里**明写「不是失败」**。
一个不懂说自己「我不知道」的自演化系统，比不演化的更危险 —— 这条它做对了。

### 1.4 那两步提升是真泛化，不是过拟合

轮 2 的判据：

```
dev_gain      = 0.40     heldout_gain = 0.3333
verdict       = generalize
discriminative= True
out_of_reach  = ['easy']  ← 分层里没涨的被单独标注为能力边界，不是被藏起来
```

dev 与 held-out **同时**涨才放行；并且把分层里没涨的那一档**显式**标出来。
这是「泛化判据」该有的样子。

### 1.5 归因到每一层、每一步

```
layer_credit.per_layer  L0=0 L1=1 L2=1 L3=1 L4=0
layer_credit.joint_ablation  {'L3+L4': 1.0}  ⇒ redundant=['L3+L4']
   「⚠️ L3+L4 联合消融才显出贡献 ⇒ 这两层互为备份，单看 per_layer 会低估它们」
step_credit.per_step   [0.0, 0.0, 1.0, 0.0]
```

**联合消融发现过互为备份的层** —— 单看每层会低估，这是真归因而不是记账。
这不是日志，是真正的归因科学。

### 1.6 执行权在人

`caps approve` / `cleanup approve` **没有 `--yes` 一律不推进**；
`cleanup patch` 只打印补丁给人，**本命令不执行**。
这条边界画得对，不许动。

## 2. 反方：四个致命问题

### 2.1 【一票否决 · 已修】史上从未走过第 3 代

把 87 次 `harness.commit` 按 `parent_id` 重建血缘：

```
距种子 1 代：73 次
距种子 2 代：14 次
第 3 代及以上：0 次        ← 从来没有
```

**历史上唯一那条 2 代链**：

```
seed(df9bf305) ─r1─▶ fix_control_flow (0.6) ─r2─▶ fix_literals (1.0)
```

根因在 `cli.py` 的 resume 判断（旧代码）：

```python
rounds_left = cpx.rounds_total - cpx.round_no   # 两个数都来自 checkpoint
if cpx.rounds_left <= 0: return 0               # 「已全部跑完」
```

上一次运行**必定**写到 `round_no == rounds_total` 才收尾 ⇒ `rounds_left` 恒为 0
⇒ **无论本次命令行传 `--rounds` 多少，都判「已跑完」**。

实测：`--rounds 2` 之后 `--rounds 4 --resume`、`--rounds 6 --resume`，
两次都直接 `return 0`，账本零新增。

生产侧佐证：34 次 `run_config` 中 `checkpoint` 全为 `None`、`resumed_from` 全为 0
⇒ **34 次运行没有一次续跑过**。想续也续不动。

> r47 已修（抽成纯函数 `resume_window(target, done)`，
> 语义改为「目标总轮数来自命令行，而非 checkpoint」）。
> 修复后实测：`resumed_from 0 → 2 → 4`，账本轮号跨进程连续到 6。
> 契约：`tests/contract_resume_window_test.py`（A–E 组 19 条，D 组反证 + E 组端到端）。

### 2.2 【根因 · 未修】世界只有 4 个玩具，两步就满分

修完 resume 后重跑，结果没变：

```
跨三次运行跑到第 6 轮 ⇒ 提交仍然只有 2 次、仍然只有 2 代
```

因为轮 3 就 `no_weakness_evidence` 停机了。**两个问题是独立的**：

- 题面：`tasks/` 下只有 `textscore / eventflow / stateflow / scheduler` 4 个环境，
  每个就一个 `task.py` + 一份 `tests.json`（3–5 条 check）。
- 结果：`fix_control_flow` + `fix_literals` 两个胶囊就把 dev 集打满 ⇒
  `reward = 1.0`，没有失败 ⇒ 没有弱点 ⇒ 没有提议。

**20,793 行进化引擎的能力上限，被 4 个小函数锁死了。**

### 2.3 【浪费】环境实际只用到一半，提议器从未上线

34 次 `run_config` 的分布：

```
dev_env      textscore 30 / scheduler 2 / stateflow 1 / None 1
heldout_env  eventflow 33 / None 1
proposer     template 33 / None 1    ← LLM 提议器 0 次
```

刻意为泛化准备的 4 个环境，实际只跑了 1 组 dev/held-out 配对；
「both」胶囊开关也只有一种提议器被走到过。

### 2.4 【自我指涉】账本里 71% 是它自己跑自己

把账本按 `run_config` / `harness.init` 切成 93 段：

- 其中 **66 段**形态一致：`commit=1, rounds=[1], verdict=6/12` ⇒ 契约 fixture
- 35 段 `commit=0`
- 真正有分量的只有早期 1 段（`commit=17, verdict=495`）

⇒ **4,989 条事件里大约七成是它自己跑自己留下的。**
归因任何读数前必须先排除这一段（第 27 条：归因前先排除 fixture）。

## 3. 根因归并

```
        「自演化」没兑现
              │
      ┌───────┴────────┐
   ①参数语义死锁      ②能力饱和
   resume 恒判跑完     世界太小，2 步满分
      │                   │
   已修（r47）        未修 · 需扩任务源
```

**① 不等于 ②**。修 ① 的意义不是让系统变强，
而是让人第一次能诚实看到：**天花板在世界，不在机器。**
在此之前，「只能进化两代」会被错读成「机器只能消化两代」。

## 4. 保留 / 删除清单

### 4.1 保留（核心资产，不许动）

这 8 个是「可验证自演化」的最小闭包：

| 模块 | 为什么必须留 |
|---|---|
| `ledger` (750) | hash 链 + 27 种受控事件，唯一事实源 |
| `genome` (705) | Harness 五层结构，变异的载体 |
| `verifier` (473) | **奖励只来自执行判据**，不是自述 |
| `nongression` (418) | 非回归闸，r44 反证组证明有牙 |
| `environment` (1241) | 任务合成 + 难度分层，能力容量的来源 |
| `checkpoint` (276) | 跨进程累积的唯一通道 |
| `generalization` (500) | dev/held-out 双涨才放行，防过拟合 |
| `attribution` (181) | 逐层 + 逐步 + 联合消融 |

外加：**53 份契约与其反证组传统**。

### 4.2 删除候选 —— 诚实说，目前**没有足够证据**

⛔ 静态分析已经否掉「没人 import」这个理由：零引用模块只有 `__main__.py`。

真正被怀疑的只有一处：**`serve.py` (1026) + `ui.py` (181) = 1,207 行 Web UI。**
疑点：没有任何运行时读数证明它被走过（无 `cap.invoke` 记录、无 CLI 调用记载），
而它是维护成本最高、离核心使命最远的一块。

但 ⛔ **我不建议现在删**。「两千行的怀疑 ≠ 两千行的错」
—— 与第 21 条同族，我在 r46 用 prune 的事实测过一次：**怀疑错了**。

**建议改为「冻结 + 判定阈值」**（一个季度为期）：

- 冻结：不再新增功能，只修崩溃
- 阈值：若下一个季度内 `serve` 相关的运行时读数（真调用事件）仍为 0
  ⇒ 归档到 `archive/`，并从回归套件里摘掉

同理，`retrieval`(253) 只有 1 处契约提及，同等处理。

### 4.3 顺手可以做的一次清理

`docs/` 下堆积了 **20+ 个 `demo_report_*` / `probe_*` 一次性产物**，全部入库。
它们曾有价值，现在只是噪音。建议归档到 `docs/archive/2026-10/`。

### P0 ✅ 已做：修 resume 死锁
一行语义修正 + 抽出可测接缝 + 19 条契约（含反证 + 端到端）。

### P1 🚧 扩大世界 —— **这是接下来唯一的真问题**

「自演化」走不动，不是因为提不出更好的变异，是因为**没有题可做**。
三个来源，按性价比：

1. **自举（bootstrapping）**：把 V6 自己的 53 份契约当任务。
   每份契约都是「改了要碎」的真实约束，且天然可判定。
   这一步不需要新数据，明天就能做。
2. **外部真实缺陷语料**：真实 repo 的真实 issue + 其 regression test。
   reward 天然有分层，不容易一步满分。
3. **难度生成器参数化**：现在 `environment.py` 能合成变异题，
   但深度只有 1。把 depth / kinds 组合成一个**可扩展的能力梯子**，
   让 `reward` 的上限随难度层数一起长。

⛔ 判定成功与否的唯一标准：**账本里第一次出现「距种子第 3 代」的提交。**

### P2 提高骨骸利用率
- dev/held-out 配对从 1 组扩到全部 4×3 配对（现在 30/34 跑同一组）
- 把 LLM proposer 真正接进生产（当前 0 次）

### P3 周期性违约金
- 每季度跑一次 `scripts/audit_zero_events.py`，看「未验证清单」是否变短
- 每次修 bug 先跑反证组，再下结论（第 21 条已经变成肌肉记忆了）

## 6. 做下去的意义：它到底能成为什么

### 6.1 它现在不是什么

它**不是**一个能接活干活的 Agent。它的解题能力等价于「按两个预置胶囊改 4 个小函数」。
拿它去和任何 coding agent 比生产力，是拿显微镜去劈柴。

### 6.2 它真正的产品

> **它不是「会进化的系统」，而是「能可信地回答『到底有没有进化』的系统」。**

这句话值很多钱。理由：

现在所有人都在做 self-improving agent，但行业里**没有**一个能回答：
「这次改动是真的能力提升，还是对评测集的过拟合？」
「变强是来自哪一层、哪一步？」
「如果退化了，能不能回滚并复现？」

V6 手上恰好握着这个问题的完整答案：

| 能力 | 落点 | 已验证 |
|---|---|---|
| 奖励只来自执行判据，不自述 | `verifier` | ✅ 是的 |
| dev/held-out 双涨才放行 | `generalization` | ✅ discriminative |
| 分层报告：涨了哪档、哪档是能力边界 | `by_difficulty` | ✅ out_of_reach |
| 逐层 + 逐步归因 | `attribution` | ✅ 发现 L3+L4 互为备份 |
| 防回归，且安全范围随 best 升级 | `nongression` + `_rebaseline` | ✅ 4→6→8 |
| 不可篡改、可重放的审计链 | `ledger` hash 链 | ✅ |
| 会在无事可做时诚实停机 | `evolution.stopped` | ✅「不是失败」 |

这一整套，是**自演化领域的度量衡**。

### 6.3 三级终局

| 阶段 | 它是什么 | 靠什么达成 |
|---|---|---|
| **近** | 自演化算法的可信对照实验装置 —— 换一个提议器/闸门/扰strate elși 策略，能在同一台仪器上比出真假 | 现有的 strict 判据 + 账本 |
| **中** | 可信的自改进引擎 —— 接真实任务流，每次自我修改都能向人给出「这次值不值、涨在哪、能不能回滚」的证据 | P1 扩世界 + P2 配对扩充 |
| **远** | **自我改进的度量衡** —— 「AGI 能不能可靠地改进自己」这件事的判据标准 | 前两级做实之后的水到渠成 |

### 6.4 一句话回答「值不值得做下去」

值得 —— 但**理由必须换**：

不是因为它现在能进化（它并不能，它在第 3 步就撞到天花板了），
而是因为当别人开始声称自己的系统在自我改进时，
在一个人人都在说「我的模型会自己变强」的时代，
**唯一一台能当场证伪这种声称的机器**，是稀缺资产。

在一个人人都在说「我的模型会自己变强」的时代，
能分辨「真变强」和「假装变强」的东西，是稀缺资产。
