## 2. 根因 1：`all_thin` 判据自锁（**不改代码**）

A 组 r2–r6 每次都是同一张脸：

```
headroom      = {'easy': 0, 'hard': 2}      # hard 层只剩 2 条空间（门槛 3）
by_difficulty = {'easy': 0, 'hard': 1.0}    # hard 层其实涨满了
thin=['easy']  saturated=['easy']            # easy 同时被判「样本不足」和「已饱和」
discriminative = true                        # 系统自己算得出它有判别力
dev_gain = 0.4   heldout_gain = 0.4          # 涨了
⇒ all_thin（每层空间都 < 3）⇒ verdict=inconclusive ⇒ 拦 ⇒ revert
```

判据要求「**每层**都要有 ≥3 条可提升空间才作证」，于是：
- `easy`（已饱和，永远不可能 ≥3）投了永久否决票；
- `hard`（有 2 条、涨满了）因为 2 < 3 也不作数；
- 明明 `discriminative=true` 的裁决，被判成「无从判别」。

### 破法早就存在，并且有效

`generalization.py` 的注释在 r52 就写明了这件事：「明知有 +0.4 的增益，
也只能三轮逐字重复地拦着」。r53 修好了出路 `--ho-grow`（补 held-out 卷子）。

**E 组实测**：补 4 条题（5→9 题，hard 层空间 2→**6**）⇒ 同一个候选
`fix_literals` 从「连拦 5 次」变成「第 2 轮提交」（advantage **1.7321**），
revert 5→**0**。E 组 r3 才停，停的时候 `headroom={easy:0, hard:0}` +
发展集无失败 —— **那才是真到顶**。

### 为什么不把它默认开

它换的是**考卷**，不是判据 ⇒ 开了就与历史基线不可比（第 33/34 条）。
⇒ **不改默认**，改成让它**可见**：新增运行级事件 `evolution.no_evidence`。

```json
{"n_blocked": 5, "capsules": ["add_skill:fix_literals"],
 "max_heldout_gain": 0.4, "min_headroom": 0,
 "note": "这些拦截是 held-out **判别力不足**（不可判别），不是候选有问题",
 "escape_hatch": "--ho-grow（补 held-out 卷子；默认关，开了与历史基线不可比）"}
```

第 35b 条：reason 里写的出路，系统必须真有 ⇒ `--ho-grow` 是 CLI 上真实的
开关，且实测有效。

### 一个被证伪的候选修法（负结果，记下来免得有人再试）

第一直觉是「`all_thin` 应该排除已饱和层」。算过：A 组 r2 排除 `easy` 后
只剩 `hard`（2 < 3）⇒ `all_thin` 仍为真 ⇒ **破不了**。判据本身一个字没改
（契约 T7 钉住）。

## 3. 根因 2：`inconclusive`（不可判别）被当成「被拦」（**已修**）

`_deadend_accum` 原逻辑是「不是 `generalize` 就 +1」：

⇒ 第 11 条（不可判别 ≠ 有罪）的实证命中：**把「尺子太短」写成了「世界的

```python

```

判据**没放松**：`overfit` / `partial`（有证据的讨好与挑食）照旧 +1
（契约 T3 钉住）。

**`inconclusive` 0** ⇒ 改这条口径在生产上**零决策翻转**（契约 T6）。

## 12. 项 6：两个开关不叠加，但**不是**因为开关没用

### 12.1 设计：先把「用武之地」定下来，再谈有没有效

⛔⛔ 第 51 / 72 条：`gain=0` 与「从没被测过」在外部**无法区分**。所以本轮
**不先看 commit/revert**，先定三个读数，缺一不许下结论：

| # | 读数 | 作用 | 不成立时的结论 |
|---|---|---|---|
| ① | `experience.propose.retry_every` = 2 | 开关真传进了 proposer | 没接线 |
| ② | `recall` = `ok` | 记忆**装了**（不是 `no_memory`/`degraded`） | 没装记忆 |
| ③ | `n_known_history` > 0 | 有失败史 ⇒ 出口**有对象** | 零原料 |

三条全成立而 `probation_released` 仍 = 0 ⇒ 才配叫「负结果」。

### 12.2 三组对照（同 seed=7 / rounds=6 / max-tasks=12 / dev=textscore / ho=eventflow）

| 组 | 变量 | commit | revert | probe | 耗时 | ① retry_every | ② recall | remembered | ③ known_hist | skip | probation |
|---|---|---|---|---|---|---|---|---|---|---|---|
| K | `--ho-grow` | 2 | 0 | 2 | 75s | **0** | ok | 0 | 0 | 0 | 0 |
| J | `--ho-grow --retry-every 2` | 2 | 0 | 2 | 94s | **2** | ok | 0 | 0 | 0 | 0 |
| L | `--retry-every 2` | 1 | 5 | 6 | 72s | **2** | ok | 0 | 0 | 0 | 0 |

**① J 与 K 逐字同形**（commit 2/2、revert 0/0、probe 2/2）⇒ **不叠加**，
H1（两者正交：一个管考卷、一个管候选过滤）成立。

**② 但 H2 无法验证**：我原本假设「`--ho-grow` 让 revert 5→0 ⇒ 被拒候选变少
⇒ 把 `--retry-every` 的原料抽干了」。实测**三组原料全是 0**（连不开
`--ho-grow` 的 L 组也是 0）⇒ 两个假设在本次数据下不可分辨。

**③ 真成因是「零原料」，不是「机制失效」**：

- `recall=ok` ⇒ 记忆**装了且检索成功**（干净排除了「没接线」）；
- `remembered=0` ⇒ 一次都没写过失败史；
- 为什么？`MemoryAwareProposer.remember` 只在 reason 含
  `gate_reject/overfit/partial/blocked/apply_failed` 时才记。而本世界 6 轮的
  裁决只有 `generalize`（K/J 组，全提交）和 `inconclusive`（L 组）——
  **`inconclusive` 不在那五个 bad mark 里**（它本来也不该在，第 11 条：
  不可判别 ≠ 有罪）⇒ 从来没有东西可记。

⇒ **`--retry-every` 有牙（`retry_every=2` 确实进账本），但本世界没有
需要重审的旧判定**。这是「无用武之地」，与项 5 的 `--gate-tries` 同形。

⛔ 耗时 J 94s vs K 75s 看着像慢了 25%，但**单跑一次的耗时不能当对照**
（项 4 实测组内极差 ±20s ≫ 组间差）⇒ 不做判据。

### 12.3 处置：不改代码，补契约

## 13. 项 7：陈述性知识层不是「零产出」，是**产出了一堆空壳**

> ⛔ 这一节推翻了 §10 表格里第 5 行的旧结论。旧结论是「知识层生产零产出，
> 成因是生产全是 1 轮短跑」。**短跑只解释「写得少」，解释不了「写得空」。**

### 13.1 生产实测（不是推断）

| 读数 | 值 |
|---|---|
| `knowledge.ingested` | **28 条**（不是 0 —— 历史结论已过时） |
| 其中 `below_min_content=true` | **24/28** |
| 不同 `note_id` | 只有 **2 个** |
| `weakness.mined` | 173 条，**111 条（64%）evidence 为空** |
| 弱点 `kind` | **100% 是 `missing_skill`**（保守默认值） |
| 空证据的 `topic` | `t0`(77) / `t3`(33) / `t7`(1) —— 全是**任务 id 退化** |
| 库里 learner 通道条目 | 只有 **3 条** |

库里那 3 条的对比最能说明问题：

| content | 长度 | `access_count` |
|---|---|---|
| `missing_skill / textscore：checks_failed:hollow_empty; …` | 79 | **1814** |
| `missing_skill / textscore：checks_failed:normalize_basic,…; …` | 112 | **1602** |
| `missing_skill / t0：` | **19** | **1** |

⇒ **空壳知识写了，但从没被检索用过**（`access=1`）；有内容的那两条被用了
1600+ 次。写入端「成功」≠ 可用（第 48 条，V5 那条同形病）。

### 13.2 根因：失败原因**两处不同源**

```python
# evaluate_dev（落库用）—— 有 fallback
"error": v.error or ("checks_failed:" + ",".join(失败检查名))

# _runs_from_verdicts（弱点挖掘用）—— 没有 fallback
payload={"error": v.error or "", ...}
```

而 `run_round` 的 MINE 步骤**只**走后者（`evolution.py:1630`）⇒ 挖掘侧拿到
的 `error` **恒为空** ⇒ `mine_weaknesses` 里 `if err:` 永不成立 ⇒
`w.evidence` 永不 append ⇒ 知识条目退化成 `missing_skill / t0：`（19 字）。

那两条**有内容**的知识是旧路径（当时 MINE 走 store）留下的化石 —— 这也
解释了为什么它们 `source=round1` 而 topic 是真实的 `textscore`。

**取证**（同 seed 探针，不改生产代码）：30 条 run payload 的 `error`
**100% 为空**，但 15 条失败裁决的 `checks` 里**全都有失败项**
（如 `["clamp_low","clamp_high","clamp_mid"]`）⇒ fallback 能补 **15/15**。
另外 15 条 `all_pass` 是 `passed=true` 的 run，本就不进挖掘。

### 13.3 修法与对照

抽 `_verdict_error()` 单一实现，两处都调它（第 13 条）。**唯一变量 =
`evolution.py` 版本**，同 seed=7 / rounds=6 / max-tasks=12：

| 读数 | 修前 | 修后 |
|---|---|---|
| 弱点 `evidence` 为空 | **6/6（100%）** | **0/6（0%）** |
| 知识 `preview` 长度 | 19 字 | **60 / 44 字** |
| `commit` / `revert` | 1 / 5 | **1 / 5（不变）** |
| 裁决序列 | generalize + 5×inconclusive | **逐字相同** |
| 总事件数 | 231 | **231（不变）** |

⇒ 修对了，且**没翻车**。`classify_error` 对 `checks_failed:` 不命中任何
needle ⇒ 弱点 `kind` 仍为 `missing_skill` ⇒ 提议方向不变，回归面为零。

唯一的行为差异（如实记录，契约 Y3.1b 钉住）：旧写法在「error 空**且**无
失败检查」时会拼出噪声串 `"checks_failed:"`（说了失败却一个名字都没列），
新写法返回 `""`。该分支下游无人消费。

### 13.4 ⛔ 诚实残留：两条里只有一条过得了闸

生产 `min_content_len=60`。修后库里两条 learner 条目的**真实**长度
（注意账本里的 `preview` 只截断显示 60 字，别拿它当全长）：

| content | 真实长度 | 生产口径（≥60） |
|---|---|---|
| `missing_skill / t0：checks_failed:clamp_low,clamp_high,clamp_mid` | **63** | ✅ 跨过 |
| `missing_skill / t3：checks_failed:top_n_basic` | **44** | ❌ 仍 `below_min` |

⇒ **1/2 跨过、1/2 仍被加载侧拒载**（第 59 条：别写「全部还是过不了」这种
全称量词）。修前是 **0/2**（两条都是 19 字空壳）。

这次修的是「**有没有证据**」，不是「**够不够长**」。要垫过 60 字只能：

- 降 `min_content_len` —— **不做**，那是改判据（第 34 条）；
- 让同一弱点聚合到 ≥2 条证据（`evidence[:2]` 拼起来会 >60）—— 依赖
  `n_failed≥2`，不是我能造的；
- 往条目里塞更多信息 —— 会改知识语义，属方向性决定，交给人定。

⇒ 现状如实写进契约 Y4.3，读数继续留在 `n_below_min_content` 里观察。
