## 1. r58 的两条结论被证伪

### ① 「换世界才破天花板」—— 错

**B 组与 A 组逐字同形**：commit 1 / revert 5 / held-out 0.6 / advantage
1.347，连停机轮都一样。

换世界**确实被走到了**（不是没接线）：冻结套件从 8 题撑到 **26 题**，
非回归闸的判别力 4 → 14。r58 报告里那个「26 题硬顶」的出处就是它。

⇒ 但它对「能进化几代」**零影响**。第 39 条：换世界增强的是**非回归闸**，
卡点在**泛化闸** —— 必要 ≠ 充分。

### ② 「easy 层结构性饱和导致 2 代」—— 错（因果搞反了）

`easy` 层 headroom=0 是**修好了的结果**，不是卡点。真卡点在下面的自锁。

## 2. 根因 1：`all_thin` 判据自锁（**不改代码**）

A 组 r2–r6 每次都是同一张脸：

```
headroom      = {'easy': 0, 'hard': 2}      # hard 层只剩 2 条空间（门槛 3）
by_difficulty = {'easy': 0, 'hard': 1.0}    # hard 层其实涨满了
thin=['easy']  saturated=['easy']            # easy 同时被判「样本不足」和「已饱和」
discriminative = true                        # 系统自己算得出它有判别力
dev_gain = 0.4   heldout_gain = 0.4          # 涨了
⇒ all_thin（每层空间都 < 3）⇒ verdict=inconclusive ⇒ 拦 ⇒ revert
```

判据要求「**每层**都要有 ≥3 条可提升空间才作证」，于是：
- `easy`（已饱和，永远不可能 ≥3）投了永久否决票；
- `hard`（有 2 条、涨满了）因为 2 < 3 也不作数；
- 明明 `discriminative=true` 的裁决，被判成「无从判别」。

### 破法早就存在，并且有效

`generalization.py` 的注释在 r52 就写明了这件事：「明知有 +0.4 的增益，
也只能三轮逐字重复地拦着」。r53 修好了出路 `--ho-grow`（补 held-out 卷子）。

**E 组实测**：补 4 条题（5→9 题，hard 层空间 2→**6**）⇒ 同一个候选
`fix_literals` 从「连拦 5 次」变成「第 2 轮提交」（advantage **1.7321**），
revert 5→**0**。E 组 r3 才停，停的时候 `headroom={easy:0, hard:0}` +
发展集无失败 —— **那才是真到顶**。

### 为什么不把它默认开

它换的是**考卷**，不是判据 ⇒ 开了就与历史基线不可比（第 33/34 条）。
⇒ **不改默认**，改成让它**可见**：新增运行级事件 `evolution.no_evidence`。

```json
{"n_blocked": 5, "capsules": ["add_skill:fix_literals"],
 "max_heldout_gain": 0.4, "min_headroom": 0,
 "note": "这些拦截是 held-out **判别力不足**（不可判别），不是候选有问题",
 "escape_hatch": "--ho-grow（补 held-out 卷子；默认关，开了与历史基线不可比）"}
```

第 35b 条：reason 里写的出路，系统必须真有 ⇒ `--ho-grow` 是 CLI 上真实的
开关，且实测有效。

### 一个被证伪的候选修法（负结果，记下来免得有人再试）

第一直觉是「`all_thin` 应该排除已饱和层」。算过：A 组 r2 排除 `easy` 后
只剩 `hard`（2 < 3）⇒ `all_thin` 仍为真 ⇒ **破不了**。判据本身一个字没改
（契约 T7 钉住）。

## 3. 根因 2：`inconclusive`（不可判别）被当成「被拦」（**已修**）

`_deadend_accum` 原逻辑是「不是 `generalize` 就 +1」：

```
r2–r5 连得 4 次 inconclusive ⇒ streak=4 ≥ 门槛 3
⇒ 判成**死路** ⇒ 冷却（deadend.cooldown）
⇒ 晋升成陈述性知识（world_fact.promoted）写进基因组 —— 跨代继承、换运行不掉
```

而 E 组证明那个候选 **advantage 1.7321、第 2 轮就提交** —— 它根本不是死路。

⇒ 第 11 条（不可判别 ≠ 有罪）的实证命中：**把「尺子太短」写成了「世界的
事实」，并继承下去。**

### 修法

```python
NO_EVIDENCE_VERDICTS = frozenset({"inconclusive"})
# 不可判别 ⇒ 不计入、也不归零（不是成功的证据，不该清零别人的账；
#                          也不是失败的证据，不该给自己累加）
```

判据**没放松**：`overfit` / `partial`（有证据的讨好与挑食）照旧 +1
（契约 T3 钉住）。

### 零回归面：先做交叉表再改

生产账本 116 条 `gen.probe`：`generalize` 96 / `overfit` 20 / `partial` 1 /
**`inconclusive` 0** ⇒ 改这条口径在生产上**零决策翻转**（契约 T6）。

### 修后对照（A2 组，其余与 A 组完全相同）

| | 修前 | 修后 |
|---|---|---|
| commit | 1 | 1（`all_thin` 没动，符合预期） |
| `deadend.cooldown` | **1** | **0** |
| `world_fact.promoted` | **1** | **0** |
| `inconclusive` 次数 | 4 | 5（r6 也重探了一次） |

**代价（如实记）**：不再冷却 ⇒ 每轮会重新探测那些「看不清」的候选 ⇒ 多花
一次探测预算。**宁可多探，不可误判死路。**

## 4. 项 3：前提不成立，但挖出一个真的 key 漂移

### r58 说要做的「迁移机制」—— 没有数据可迁

| 取证项 | 实测 |
|---|---|
| 生产 `env_pair` | 89 条**全是具体值**，`unknown` **0 条** |
| 生产 `deadend.*` / `world_fact.*` | **0 条** |
| 18 个 harness 快照的 `world_facts` | **全部为空**（payload 恰好只缺这一层） |

⇒ 那条「历史」来自 `world_facts.py` 的**文档注释**，被当成了生产现状
（第 24 条第十次命中）。

真成因：生产 15 次运行里 **14 次是 `rounds=1` 的短跑**，而死路门槛是「连续
3 次」⇒ 1 轮根本攒不到。r59 的 6 轮对照里它们**真的产出了**（与第 64 条同形：
轮数不够会伪装成结构性不可达）。

⇒ **不做迁移机制**。改成把「前提不成立」这件事用**读数**钉住（契约 U5/U6）：
哪天 `n>0` 了，就说明前提变了，项 3 要重开。

### 但取证时挖到一个真的（潜伏的）key 漂移

知识侧推导 pair 时写了：

```python
W.env_pair_key(*str(env_pair).split("|", 1)) if "|" in str(env_pair) else str(env_pair)
```

而 `env_pair` 的生产源是 `f"{'|'.join(devs)}->{ho}"` —— **有向**的发展集→
held-out 对。`env_pair_key` 做的是**顺序无关**规范化，用在这里语义是错的：

| env_pair | 知识侧（旧） | 账本侧（`_deadend_accum` 用原值） | 同源？ |
|---|---|---|---|
| `textscore->eventflow` | 同 | 同 | ✅ |
| `alpha\|beta->ho` | `alpha\|beta->ho` | `c1\|alpha\|beta->ho` | ✅ |
| **`zeta\|alpha->ho`** | **`alpha->ho\|zeta`** | `c1\|zeta\|alpha->ho` | ❌ |

⇒ 同一个 (候选, 环境对) 在两处是**两个 key** ⇒ 「继承的知识优先于本轮派生量」
（`_facts_deadend_streak`）会查不到自己刚写进去的东西。

**当前未触发**（生产 dev 只有一个环境 ⇒ 值里不含 `|`）。已在多 dev 时埋雷。

修法：抽成 `_deadend_pair()` 直接返回原值（它已是规范形式：`dev` 侧 sorted、
`->` 定方向）。**零影响**：单 dev 时新旧两法逐字相同（契约 U4）。
